# Haier Evo integration
[![hacs_badge](https://img.shields.io/badge/HACS-Custom-orange.svg)](https://github.com/custom-components/hacs) [![stability-beta](https://img.shields.io/badge/stability-beta-33bbff.svg)](https://github.com/mkenney/software-guides/blob/master/STABILITY-BADGES.md#beta)

Неофициальная интеграция для работы [Haier Evo](https://haieronline.ru/evo-iot/) (RU, KZ, BY).

Бета-версия: может работать некорректно.

> **Это форк** [and7ey/haier_evo](https://github.com/and7ey/haier_evo) (версия 0.4.0-dev).
> Домен тот же (`haier_evo`), поэтому одновременно с апстримом не ставится.
> Что изменено — в разделе [«Отличия от апстрима»](#отличия-от-апстрима).

## Поддерживаемые устройства
Ниже приведен список типов устройств, работа с которыми была **проверена пользователями**:

- Кондиционеры
- Холодильники

В действительности интеграция должна поддерживать больше устройств. 
Если интеграция некорректно работает с вашим устройством или поддерживает не все функции - сообщите в [Issues](https://github.com/temandroid/haier_evo_2/issues) об этом. 

## Совместимость
Haier предлагает разные мобильные приложения для разных рынков и стран. Некоторые устройства совместимы с более чем одним приложением. Эта интеграция поддерживает только устройства, которыми можно управлять через приложение [Evo](https://haieronline.ru/evo-iot/). Загрузите приложение Evo и проверьте совместимость с вашим устройством.
Приложения из этого (неполного) списка на данный момент запрошены:

| Приложение      | Рынок         | Совместимость                           | Альтернатива                                                                    |
|-----------------|---------------|-----------------------------------------|---------------------------------------------------------------------------------|
| Haier Evo       | Россия        | :heavy_check_mark:                      |                                                                                 |
| Haier hOn       | Европа        | :x:                                     | [Andre0512/hon](https://github.com/Andre0512/hon)                               |

## Установка

### 1. Установка HACS (если не установлен)
Для работы интеграции требуется наличие HACS.
Инструкция для установки https://www.hacs.xyz/docs/use/download/download/

### 2. Добавление репозитория Haier Evo

Так как интеграция является кастомной, её необходимо добавить в HACS как пользовательский репозиторий:

1. Откройте **HACS** в боковой панели Home Assistant.
2. Нажмите на три точки (⋮) в верхнем правом углу и выберите **Custom repositories** (Пользовательские репозитории).
3. В поле **Repository** вставьте ссылку: `https://github.com/temandroid/haier_evo_2`
4. В поле **Category** выберите **Integration** (Интеграция).
5. Нажмите **Add** (Добавить).
6. Теперь найдите **Haier Evo** в поиске HACS и нажмите **Download** (Загрузить).

### 3. Настройка

1. Перезапустите Home Assistant.
2. Перейдите в **Настройки** > **Устройства и службы** > **Добавить интеграцию**.
3. Найдите в списке **Haier Evo** и введите данные вашего аккаунта от приложения Evo.

Если аккаунт Evo заведён через **Яндекс ID**, пароля у него нет и мастер ответит
«Неверный email или пароль». Задайте пароль через «Забыли пароль» **в приложении Evo**
(не на сайте haieronline.ru — там пароль не синхронизируется), на тот же email.

Логин и пароль меняются через **⋮ → «Перенастроить»** у записи интеграции. Если облако
перестанет принимать пароль, HA сам предложит войти заново.

## Отличия от апстрима

- Сеть переписана на `aiohttp`: никаких потоков и блокирующих `requests`, сторонних
  зависимостей в `manifest.json` больше нет.
- **WebSocket не теряет команды** ([#89](https://github.com/and7ey/haier_evo/issues/89),
  [#102](https://github.com/and7ey/haier_evo/pull/102)): мёртвое соединение ловит heartbeat,
  команда ждёт переподключения, неудачная запись повторяется на новом сокете, а команда без
  `command_response` за 10 с отправляется ещё раз. Если отправить не удалось, вызов сервиса
  завершается ошибкой, а не делает вид, что всё прошло.
- **Доступность честная** ([#103](https://github.com/and7ey/haier_evo/issues/103)): устройство
  `unavailable`, если оно `OFFLINE` или облако недоступно дольше 3 минут. После обрыва и раз в
  15 минут состояние перечитывается по REST.
- `'None' is not a valid HVACMode` исправлен в корне ([#61](https://github.com/and7ey/haier_evo/issues/61),
  [#73](https://github.com/and7ey/haier_evo/issues/73)): неизвестный код режима — это `unknown`,
  а в устройство больше не уходит значение `"None"`.
- Мастер настроек проверяет логин, отличает неверный пароль от 429 и недоступного облака
  ([#87](https://github.com/and7ey/haier_evo/pull/87)), есть reauth и «Перенастроить».
  Сломанный OptionsFlow удалён ([#96](https://github.com/and7ey/haier_evo/issues/96),
  [#98](https://github.com/and7ey/haier_evo/pull/98)).
- Пустой список устройств или сбой облака при старте — повтор через `ConfigEntryNotReady`
  ([#105](https://github.com/and7ey/haier_evo/pull/105)), неверный пароль — reauth.
- Токены хранятся в `.storage/haier_evo.<entry_id>`, а не в `/config/haier_evo`.
- Отладочный эндпоинт `/api/haier_evo` **удалён** ([#100](https://github.com/and7ey/haier_evo/pull/100)):
  он отдавал данные без авторизации. Вместо него — **диагностика** (⋮ → «Скачать диагностику»),
  email, MAC, серийники и токены в ней скрыты.
- «Тихий» и «Турбо» показывают состояние с устройства, при перезапуске HA кондиционеры больше
  не пищат ([#67](https://github.com/and7ey/haier_evo/issues/67)). Включение всегда шлёт `status=on`.
- Профиль модели из `/config/haier_evo.<МОДЕЛЬ>.yaml` по-прежнему главнее встроенного, но
  автоматически больше не создаётся (раньше копия навсегда замораживала профиль).
- `logger:` из `configuration.yaml` снова работает для `custom_components.haier_evo`.
- Профили `AS25PHP3HRA` и `AS70S2SF2FA` (пока копии соседних моделей, на живом не проверены).

## Разработка

Тесты гоняются на Linux (Home Assistant не работает на Windows):

```bash
python3.14 -m venv .venv && . .venv/bin/activate
pip install -r requirements_test.txt
ruff check custom_components tests
pytest -q
```

Облако в тестах замокано, фикстуры синтетические: MAC-адреса из документационного
диапазона RFC 7042, без персональных данных.
